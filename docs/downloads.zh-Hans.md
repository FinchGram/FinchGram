# 下载：媒体中心里的 WebDAV 客户端

[English](downloads.md)

状态：2026-10-16 按设计稿的这一轮（“FinchGram Desktop 下载”）做好，三套主题都有；v0.4.0 发布。

## 是什么

一个从 WebDAV 服务器取文件的页面：NAS（群晖、威联通）、seedbox、PikPak、Alist 或 OpenList（把网盘套上
WebDAV）、Nextcloud、`rclone serve webdav`，或者用 `vget serve` 共享出来的文件夹。用户添加服务器，在 app 里浏览，
挑文件或整个文件夹，文件就多连接并发地下到下载文件夹里，和维护者的命令行工具 vget 一个取法。照片和视频下完直接在
媒体查看器里打开。

FinchGram 只读：不上传、不同步、不重命名、不删除服务器上的任何东西，也不是同步客户端，要什么人来挑。

## 页面

入口：显示 → 下载（⌥⌘L），工作台活动栏和报纸侧栏里齿轮上方的下载图标（有文件在下时带一个点），终端底栏的
“[↓ 2]”，数字是正在下的文件数。这个页面不需要 Telegram 账号，登录前也能打开。

三栏：

- **WebDAV 服务器**，左栏：每个服务器的名称、主机名和状态，页面打开时检查一遍：已连接、密码被拒绝、无法连接。
  右键有编辑、移除、复制地址。最后一行是添加服务器。
- **文件夹**，中间：当前位置写成路径，“Home NAS /Movies/2026”，点路径里的文件夹就回到那一层；然后是文件夹的名称、按名字筛选列表的输入框，刷新按钮，以及显示或隐藏队列的
  “下载”按钮，上面带正在下的文件数。列表是一张表：每个文件一个勾选框、按类型的图标、名称、修改日期、大小；文件夹在前，
  然后按界面语言的顺序排名称。点一下文件夹就进去。选中的文件在表尾计数并加总大小：清除、下载，选中的唯一一个文件是
  照片或视频时还有打开。右键点文件有下载、打开、复制链接；点文件夹有打开、下载文件夹、复制链接。
- **下载**，右栏，380 px：队列。每个文件有名称、进度条、“4.1 GB / 10.8 GB · 24.3 MB/s · 剩余 5 分钟”，和一个叫停的 X。
  停下的文件写明原因和已保留多少，带重试；完成的有在访达中显示。右键有取消、重试、在访达中显示、从列表移除。栏底写着
  每个文件几个连接、下载到哪里，“更改”打开选目录的面板。“隐藏”把这一栏收起来；选择会记住，有新下载开始时这一栏会
  自己展开。队列为空时这一栏干脆不出现。

打开：先把照片或视频取下来，再在媒体查看器里显示，和看 Telegram 媒体用的是同一个查看器，沿用播放器的速度和音量。
其他文件下完后在访达里显示。下载文件夹：先把文件夹的树列全，再把每个文件按同样的树下到下载文件夹里；已经在那里且
大小相同的文件跳过。

## 一个文件怎么下来

引擎在 `src/downloads/transfer.rs`，照 vget 做：

1. 先用 `Range: bytes=0-1` 探一下前两个字节。回 206 就知道了文件大小，也知道服务器支持 Range；回 200 就是不支持。
2. 文件切成 8 MB 的块。一池 worker，每个一条连接（默认 12 条，settings.toml 里的 `connections`，1 到 32），
   谁空了谁取下一块，直到没有；每块按偏移写进 `<name>.part`，这个文件一开始就是完整大小。
3. `<name>.part.json` 记着哪些块已经完成。重试，或者以后再下同一个文件，从那里接着来：“已保留 12 MB，共 48 MB”。
4. 失败的块从最后写到的字节重来，最多十次，中间停顿从半秒涨到八秒，不管是什么错：连接断了、服务器忙回的 429 或 5xx、
   CDN 节点还没拿到文件时回的 404（PikPak 就这样）、该回 206 却回了 200；探测请求也一样重试。只有磁盘出错才立刻停。
   对 Range 回 200 的服务器，整个文件走一条连接。
5. 下完，`.part` 改成文件本名；名字被占了就是“name (2).ext”。

同时下两个文件，其余排队。只要有文件在下，app 就告诉 macOS 自己在忙（NSProcessInfo 的 activity）：窗口退到后台也不会被
App Nap 降速，Mac 也不会自己睡着。显示的速度是最近三秒的。取消会留着 `.part` 文件以便重试；从列表移除只是把停下的或
完成的文件从列表拿掉，什么都不删。

WebDAV 本身在 `src/downloads/webdav.rs`：深度 1 的 PROPFIND 列文件夹（深度 0 检查服务器），207 Multi-Status
用 roxmltree 解析，Basic 认证，地址按段做百分号编码。HTTP 用 ureq 加 rustls。

## 东西存在哪

- `settings.toml`：`[downloads]` 有 `folder`（空就是默认的 `~/Downloads/FinchGram`）、`connections`、
  `queue_shown`；`[[webdav]]` 有每个服务器的 `name`、`url`、`username`。
- 密码进 macOS 钥匙串，不进文件：一条 generic password，service 是“FinchGram WebDAV”，account 是“用户名@地址”，
  只在登录钥匙串里（不进 iCloud 钥匙串）。表单保存时存入，一次运行里第一次用到这个服务器时读出，删除服务器时删掉，
  地址或用户名改了也删旧的。线上走的是 Basic 认证：只是 base64，局域网 http 就是明文，https 才由 TLS 加密。
- 钥匙串条目归应用的签名身份所有。发布版用项目自己的证书签名，升级不变，装好的 app 读取不会弹窗；本地 ad-hoc
  签名的构建是另一个身份，macOS 可能问一次。
- 删掉 FinchGram 不会删这些，Mac 应用都这样：Application Support 文件夹留着，钥匙串条目也留着
  （钥匙串访问 → 搜“FinchGram” → 删除）。

## 还没有的

- 自签名证书（NAS 的默认）会被拒绝：rustls 只信 Mozilla 的根证书。局域网用 http，或者配个正规证书（多数 NAS
  能从 Let's Encrypt 拿）。没做“信任这张证书”的选项。
- 只有 Basic 认证：没有 Digest、没有 token、没有代理设置。
- 文件要整个取下来才能打开，不流式播放。
- 表格除了文件夹在前、名称排序之外没有别的排序，文件夹不显示大小。
- 停下的下载从列表移除后，它的 `.part` 文件留在下载文件夹里，直到再下同一个文件。

## 怎么做的

- `src/downloads/mod.rs`：页面状态在 UI 线程上，一个 worker 线程（“webdav”）负责列目录、检查服务器和表单的测试，
  每个在下的文件一个线程，引擎自己的分块 worker 在它里面。回答通过 `slint::invoke_from_event_loop` 送回；
  和 app 其他地方一样，没有 async 运行时。
- `src/platform/`：选目录的面板（NSOpenPanel）和钥匙串（objc2-security）。
- `ui/downloads.slint`（页面和 Rust 共用的 global）、`ui/pages/downloads.slint`（页面、菜单和文案，用 Look 的
  token 画，一个页面服务三套主题）、`src/telegram/viewer.rs`（`view_file`：下好的照片或视频进查看器）。
- `cargo test downloads`：列表解析、地址，以及引擎对着回环地址上一个文件服务器的测试：多连接分块、接着上次继续、
  不支持 Range 时单流、失败的块重试、密码被拒、取消。
