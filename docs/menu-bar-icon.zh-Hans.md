# 菜单栏的小鸟：有未读时一个点，来消息时跳一下

[English](menu-bar-icon.md)

状态：计划，没做。维护者 2026-11-03 问菜单栏的小鸟能不能更生动些（“你能不能把top menubar上的小鸟弄的生动活波一些，
比如，有了新消息，会跳动”），2026-11-04 让把答复写下来，等有心情再做（“这个不紧急，等我有心情了再说”）。第一节是现在的
样子；后面是计划和它依据的事实，以 0.7.9 为准。

## 现在

- 图标是一个可变长度的 `NSStatusItem`（`src/platform/macos.rs` 的 `status_item`），设置 → 通用 → “在菜单栏显示图标”
  开着时显示（0.2.13 起默认开）。按钮的图是 logo 的 mark，`ui/logo/svg/FinchGram-mark-16.svg`，由 resvg 画成 36 像素、
  按 18 pt 显示，是模板图：菜单栏深色浅色、菜单打开的那一刻，都由 macOS 上色。菜单里是“打开 FinchGram”和“退出
  FinchGram”，用界面的语言。它对账号一无所知：没有未读、没有连接状态、不动。
- 新消息现在动的是 Dock 图标（`src/telegram/notifications.rs`）：未读数，所有账号加起来，已静音的聊天只在“未读数包含静音聊天”开着时算（主聊天列表的 `updateUnreadMessageCount`，`platform::set_badge`）；FinchGram 不在前台时弹跳一次
  （`platform::flash_icon`，`requestUserAttention`），受设置 → 通知与声音 → “任务栏闪烁提醒”控制
  （`[notifications] flash_taskbar`，默认开）。弹跳和横幅在同一处发起，`group_changed`，也就是 TDLib 的通知组：所以已静音
  的聊天从不发起（TDLib 不为它生成通知），用户正看着的那个聊天也不（FinchGram 在前台、窗口在前台、聊天开着）。
- 连接状态（`updateConnectionState`：等网络、连接中、更新中、就绪）在 `src/telegram/mod.rs` 里按账号记着，窗口里显示；
  窗口之外没有任何地方显示它。

## macOS 对菜单栏图标的要求

苹果关于菜单栏的指引（https://developer.apple.com/design/human-interface-guidelines/the-menu-bar，“Menu bar extras”，
2026-11-03 读）要求图标只用黑色和透明，由系统上色，好在深浅两种菜单栏和选中时都好看；说菜单栏高 24 pt；要让用户而不是 app
决定显不显示；并提醒菜单栏地方不够时系统会把图标藏起来。对动画一个字没说。由此：

- 把彩色计数画进图里（红圆白字）不行：它就不再是模板图，app 就得自己跟着菜单栏的深浅和选中态走。黑色加透明的一个点可以，
  也很常见。
- 可以动，但菜单栏是公共区域：什么都不能动很久或一直动（Dropbox 的图标只在同步时转）。短短一跳、停在一个静止的状态，是合适的。
- 用户自己的选择优先：系统辅助功能里的“减弱动态效果”（`NSWorkspace.accessibilityDisplayShouldReduceMotion`）开着，就不跳，
  只有点。

## 计划

六条，按价值排序。

1. **有未读时一个点。** 最有用的一条：窗口收进 Dock 之后，菜单栏是唯一能看到状态的地方。小鸟右上角一个实心圆点，外面从鸟身
   上抠出一圈透明边，压在鸟身上和落在菜单栏上都看得清。它完全跟着 Dock 的数字走：同样是所有账号的和，同样受“未读数包含静音聊天”
   控制，1 就亮、0 就灭，所以在任何设备上读了都会熄灭。
2. **来消息时跳一下。** 上跳 2 到 3 pt，落地略压扁，再小弹一次，总共半秒左右，带缓动；然后小鸟带着点静止。在今天 Dock 弹跳发
   起的那一处发起，规则因此现成：已静音的聊天不跳，正看着的聊天不跳，每个账号的消息都算。和 Dock 不同的是（app 在前台时 macOS
   不让 Dock 动），小鸟在 FinchGram 在前台时也跳：维护者要的就是这个生动（见下面“待定”）。跳的过程中再来的一跳丢掉，之后
   隔几秒才跳下一次；热闹的群只换来一跳，不是一支舞。“减弱动态效果”开着就不跳。
3. **用现有的开关。** “任务栏闪烁提醒”本来就是“来消息时用动作提醒我”的意思；跳动归它管，点不归任何开关管（它就是 Dock 的数字，
   Dock 的数字也没有开关）。设置页不加新行：页面照设计画，设计没为这个画过。
4. **掉线时变灰（可选）。** 状态栏按钮的 `appearsDisabled` 按系统的方式把模板图变暗。连接不就绪超过几秒就开，恢复就关：不动，
   小鸟却多说了一件事。顺手就能做，维护者嫌多余就不做。
5. **不做的。** 不停扇翅膀，或任何循环动画；颜色；把数字当按钮标题放在鸟旁边，在常常不够用的菜单栏里占宽度（有用户要再考虑）。
6. **扇翅膀要画。** mark 是一整块剪影、一条路径；翅膀没法单独动。在 Claude Design 里画两三帧 mark 的变体，跳动的那套代码就能
   播放；跳和点不需要任何新图。

## 怎么做

- **定时器加预渲染帧，推荐。** 跳动的每一帧都是 resvg 像今天画菜单栏图标那样画出来的 mark，只是小鸟按那一刻的高度抬起、按曲线
  压扁，画进 18 pt 宽、24 pt 高（菜单栏的高度；宽度不变，所以不会挤动邻居）的图里，为 Retina 屏按 2 倍画，模板图；点由
  tiny-skia 叠上去（先用 `BlendMode::Clear` 抠一圈透明，再画圆点）。主线程上的一个 Slint 定时器（状态栏项就在主线程）每
  16 ms 换一次按钮的图，大约 36 帧，最后换成带点或不带点的静止图。不加 crate，模板上色和今天一样交给系统，测试能像 mark 的测试
  那样读帧的像素。
- **Core Animation，更顺滑。** 给状态栏按钮开 `wantsLayer`，用 `CAKeyframeAnimation` 动 layer 的位移和缩放：GPU 做缓动，
  没有定时器。要加 `objc2-quartz-core` crate（Cargo.toml 里已有的 objc2 家族）和 objc2-app-kit 对应的 feature 才有 layer
  的访问方法，还得亲眼确认开了 layer 的状态栏按钮在菜单打开时高亮画得和以前一样。只在帧看起来一顿一顿时才值得，60 帧每秒
  应该不会。
- **接在哪。** `platform::` 多两个在 macOS 之外空着的调用，和角标、弹跳一样：一个管点（从 `show_unread_count` 调，挨着角标），
  一个管跳（在 `group_changed` 里调，挨着弹跳）。做第 4 条的话再加一个管连接的，从处理 `updateConnectionState` 的地方调。
  总共 `src/platform/macos.rs` 里一两百行，`notifications.rs` 里几行。
- **怎么看到。** 截图测试（`cargo test screenshots`）画的是窗口，不是菜单栏。状态栏项和通知不同，不需要 bundle 也不需要
  api_id，所以 `cargo run` 就能在真的菜单栏里看到它；可以用一个调试用的环境变量让它跳一下、亮个点来看。维护者测的是装好的
  发布版，下一次发版就能看到。
